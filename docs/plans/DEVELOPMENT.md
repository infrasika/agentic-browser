# 开发与验收计划

目标是交付完整 Agent 私有部署。原域名测试站和用户自部署均使用同一套 Compose、镜像、配置与运维入口，架构见 [ARCHITECTURE.md](../ARCHITECTURE.md)。当前服务器已获授权用于实装与故障恢复验收；不自动扩大实际并发，不重启同机其他服务。

## 已交付

- 聊天与远程浏览器同屏、每账号一个会话、排队、人工接管和自动继续。
- 本地账号、个人 credits、全站日预算、管理员操作、Turnstile 与可选 SMTP 找回。
- 完整六镜像 Compose、本机目录持久化、一次配置、账号管理、健康检查。
- 空闲停写备份、每日调度和轮转、新实例恢复、镜像升级、普通备份中断恢复。
- 固定提交构建、离线包校验、独立 Node/Docker 安装与故障验收工具（无需宿主 Python 或 npm 依赖）。
- 原域名就地迁移；账号、聊天、余额、预算和凭据核对通过，实际备份可恢复。
- 面向开源部署者的完整安装指南：Cloudflare 入口、参数/密钥、TLS 模板、首登/邮件/浏览器验收与故障排查；共用一套 Compose、账号与 SMTP 实现。

## 后续工作

构建源统一为本仓库，使用固定 LibreChat 上游提交和仓库内补丁。Mac / Ubuntu 使用同一套双架构构建与 GHCR 发布工具，不依赖源码移交包或服务器配置。Ubuntu 只准备和验收，不执行镜像上传、Git push 或站点升级。待在 Mac 实机与原生 ARM64 Linux 主机验证，并由维护者发布镜像。

| 工作 | 完成条件 |
| --- | --- |
| 公网安装指南实装 | 在新实例按指南验证 Cloudflare Full (strict)、Turnstile、真实模型和邮件；现有测试站 HTTPS 源站切换需先配置证书 |
| 独立主机验证 | 新 Linux amd64 主机或干净 CI runner 从候选包完成安装/恢复，记录机器来源；同机验收不作此证据 |
| 实际数据库版本升级 | 在需要变更数据库版本时，验证新旧版本间的数据迁移和失败恢复 |
| 公开分发 | 明确镜像仓库与下载渠道，发布后完成匿名下载/拉取和摘要校验 |
| 异地灾备 | 配置受控外部存储，验证副本与跨机器恢复；本机目录副本不作异地证据 |
| 宿主重启演练 | 在专门授权的整机维护窗口验证 Docker 和定时器恢复；进程强杀不等于断电测试 |

先完成无需新密钥或外部资源的工作，再处理外部依赖。验收结果与具体版本统一写入 [PROGRESS.md](PROGRESS.md)。
