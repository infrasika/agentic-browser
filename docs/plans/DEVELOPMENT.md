# 开发与验收计划

目标是交付完整 Agent 私有部署。原域名测试站和用户自部署均使用同一套 Compose、镜像、配置与运维入口，架构见 [ARCHITECTURE.md](../ARCHITECTURE.md)。当前服务器已获授权用于实装与故障恢复验收；不自动扩大实际并发，不重启同机其他服务。

## 已交付

- 聊天与远程浏览器同屏、每账号一个会话、排队、人工接管和自动继续。
- 本地账号、个人 credits、全站日预算、管理员操作、Turnstile 与可选 SMTP 找回。
- 完整六镜像 Compose、本机目录持久化、一次配置、账号管理、健康检查。
- 空闲停写备份、每日调度和轮转、新实例恢复、镜像升级、普通备份中断恢复。
- 固定提交构建、离线包校验、仅 Python/Docker 的安装与故障验收工具。
- 原域名就地迁移；账号、聊天、余额、预算和凭据核对通过，实际备份可恢复。

## 当前阶段

1. 删除退役宿主部署、旧私密配置生成器与重复验收脚本；剩余测试独立于当前站点。
2. 文档只维护产品架构、开发计划、最新进度和当前部署操作。历史实现留在 Git，不保留兼容入口。
3. 从清理后的固定提交完整重建三个应用镜像，连同固定的 gateway/Mongo/Redis 生成新离线候选包。
4. 对最终候选包完成安装、真实浏览器、排队/接管、备份恢复、故障注入和清理验收。
5. 在原域名空闲时备份并升级，验证账号、聊天、预算和密钥保留。

## 后续工作

| 工作 | 完成条件 |
| --- | --- |
| 独立主机验证 | 新 Linux amd64 主机或干净 CI runner 从候选包完成安装/恢复，记录机器来源；同机验收不作此证据 |
| 实际数据库版本升级 | 在需要变更数据库版本时，验证新旧版本间的数据迁移和失败恢复 |

| 宿主重启演练 | 在专门授权的整机维护窗口验证 Docker 和定时器恢复；进程强杀不等于断电测试 |
