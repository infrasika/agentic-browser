Run your own
Agentic Browser.

Run our public Docker images with one configuration file. No source checkout or build is required.

Requires Docker Engine 26+, Compose 2.24.4+, and Bash. Supports Linux amd64/arm64 and Docker Desktop on Apple Silicon.

1. Download

Download setup files Checksum

Extract the archive and open a terminal in its agentic-browser folder. All helpers below are included.

Download and verify from the terminal 
curl -fSLO https://agentic-browser.zkpass.org/self-host/download/agentic-browser-self-host.tar.gz
curl -fSLO https://agentic-browser.zkpass.org/self-host/download/SHA256SUMS
sha256sum -c SHA256SUMS
tar -xzf agentic-browser-self-host.tar.gz
cd agentic-browser

On macOS, use shasum -a 256 -c SHA256SUMS for verification. Stop if the checksum fails.

2. Configure

cp .env.compose.example .env.compose

Edit .env.compose. The defaults work locally; change the total browser limit to suit your server:

AB_PROJECT_NAME=agentic-browser
AB_PORT=3333
AB_MAX_SESSIONS=1

For a remote team, set AB_PUBLIC_URL=https://browser.example.com and configure an HTTPS reverse proxy. Otherwise, the address defaults to http://127.0.0.1:3333.

SettingManage it in

The dashboard does not change server settings. The source-run .env file is not used by this deployment.

Limits and optional settings 
AB_MAX_SESSIONS_PER_MEMBER=1
AB_SESSION_TTL_SECONDS=1800
AB_SESSION_MAX_LIFETIME_SECONDS=14400
# AB_EGRESS_DENY_HOSTS=other-management.example.com

Each member can use one browser by default, within the total limit. The initial lease is 30 minutes; renewals cannot exceed a 4-hour total lifetime. Limits allow 1–32 browsers. See docs/SELF_HOST.md in the download for all supported values.

Only supported settings are passed into the container. For example, AB_PUBLIC_URL becomes PUBLIC_URL. Image digests come from deploy/release.env. Keep the project name stable to retain the same data volume.

Apply changes after installation

Edit .env.compose, finish active sessions, then recreate the controller:

bash scripts/release-compose.sh up -d --force-recreate --wait --wait-timeout 90

No image rebuild is needed. A plain restart does not reload these settings. Accounts and saved profiles remain in the data volume.

3. Start and sign in

bash scripts/release-compose.sh pull
bash scripts/release-compose.sh up -d --wait --wait-timeout 90
bash scripts/release-compose.sh doctor
bash scripts/release-compose.sh member create alice

Enter a password of at least 12 characters. Open http://127.0.0.1:3333 or your configured address, sign in, and create a personal Agent credential. Add a separate member for each teammate.

4. Connect your Agent

Choose where your Agent runs. Replace the setup folder path and personal credential in the configuration, then reconnect your MCP client.

Agent on the same machine

Run pwd in the setup folder to find its full path. Keep the controller running.

{
  "mcpServers": {
    "agentic-browser": {
      "command": "bash",
      "args": ["/ABSOLUTE/PATH/agentic-browser/scripts/release-compose.sh", "mcp"],
      "env": {
        "AGENT_BROWSER_URL": "http://127.0.0.1:3333",
        "AGENT_BROWSER_TOKEN": "YOUR_PERSONAL_AGENT_CREDENTIAL",
        "AGENT_BROWSER_VIEW_URL": "http://127.0.0.1:3333"
      }
    }
  }
}

For local deployments, the API uses internal port 3333; the view URL is the address you open. If you configured a public domain, use that origin for both URLs and ensure the controller can reach it.

Agent on another machine

Install Docker and extract the setup files on that machine. Pull the client image without starting another server:

bash scripts/release-compose.sh pull-client
{
  "mcpServers": {
    "agentic-browser": {
      "command": "bash",
      "args": ["/ABSOLUTE/PATH/agentic-browser/scripts/release-compose.sh", "mcp-remote"],
      "env": {
        "AGENT_BROWSER_URL": "https://YOUR_PRIVATE_BROWSER_DOMAIN",
        "AGENT_BROWSER_TOKEN": "YOUR_PERSONAL_AGENT_CREDENTIAL",
        "AGENT_BROWSER_VIEW_URL": "https://YOUR_PRIVATE_BROWSER_DOMAIN"
      }
    }
  }
}

This client uses the same published image and connects to your private service over HTTPS. It receives no server Docker permissions. More examples are in docs/AGENT_CLIENT.md.

Ask your Agent to open a website and send you a sign-in link. Complete your steps in that browser, then click Hand back to Agent.

Operation and upgrades

Images, storage, and remote access

The controller creates one isolated browser per session from the runtime image, which includes Chrome and both zkPass extensions. Only the trusted controller mounts the Docker socket. Start with one browser; each runtime has a 2 GiB memory and 2 CPU limit, plus service overhead.

Temporary browser data is cleared on close. Saved profiles persist in your private data volume; the server administrator can access that data.

For an Ubuntu website tunnel, run ssh -N -L 3333:127.0.0.1:3333 ubuntu@SERVER_IP. For team HTTPS access, follow deploy/nginx-public.conf. Setting the public URL alone does not configure DNS, TLS, or port exposure.

Before upgrading, finish sessions and back up the data volume. Retain your settings and project name. Do not use down --volumes for routine changes. See docs/SELF_HOST.md for operations and docs/PROGRESS.md for platform verification status.
