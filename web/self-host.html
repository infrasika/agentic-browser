YOUR INFRASTRUCTURE / YOUR WORKSPACE

Run your own
Agentic Browser.

Two public Docker images. One settings file. Connect your Agent with a URL and a personal token.

Requires Docker Engine 26+, Compose 2.24.4+, and Bash. Supports Linux amd64/arm64 and Docker Desktop on Apple Silicon.

1. Install

curl -fsSL https://agentic-browser.zkpass.org/install.sh | bash
cd agentic-browser

The installer pulls both pinned images and creates compose.yaml and .env. No source checkout or build is required. Existing files are never overwritten.

2. Configure and start

Edit .env. Choose your own initial account password of at least 12 characters:

AB_MODE=authenticated
AB_ADMIN_USERNAME=admin
AB_ADMIN_PASSWORD='your-own-long-password'
AB_PORT=3333
AB_MAX_SESSIONS=1
docker compose up -d --wait

Open http://127.0.0.1:3333 and sign in with that account. The account is created only on an empty workspace; restarts never reset existing passwords.

Modes and optional settings
ModeAccess
authenticated (default)Member sign-in and personal Agent tokens; private member resources
publicNo registration or Agent token; temporary sessions with individual secret keys

Use a separate directory and project name for a public demo. Both modes use the same .env and compose.yaml. Public sessions last 5 minutes initially, up to 10 minutes.

# For remote access, configure an HTTPS proxy and set:
# AB_PUBLIC_URL=https://browser.example.com
AB_MAX_SESSIONS_PER_MEMBER=1
AB_SESSION_TTL_SECONDS=1800
AB_SESSION_MAX_LIFETIME_SECONDS=14400

Server settings live in .env; personal tokens and saved profiles live in the dashboard. Keep the project name stable to retain your volume. See the full guide for supported settings and public deployment.

3. Connect your Agent

In the dashboard, create a personal Agent credential and click Copy MCP configuration. Add it to your Agent and reconnect.

{
  "mcpServers": {
    "agentic-browser-local": {
      "url": "http://127.0.0.1:3333/mcp",
      "headers": { "Authorization": "Bearer YOUR_PERSONAL_AGENT_CREDENTIAL" }
    }
  }
}

The website and MCP use the same host port. If you set AB_PORT=4444, use http://127.0.0.1:4444/mcp. Remote Agents use your HTTPS origin. Their machines do not need Docker or source files.

Codex CLI

Set AGENT_BROWSER_TOKEN in the environment used to launch Codex, then run:

codex mcp add agentic-browser-local --url http://127.0.0.1:3333/mcp --bearer-token-env-var AGENT_BROWSER_TOKEN

Try: “Use agentic-browser-local to open GitHub and send me a sign-in link. Wait until I hand control back, then count my private repositories and list their names. Check every page and close the browser when finished.”

Open the link while signed in to your workspace account, complete the website login, then click Hand back to Agent. See the client guide for details.

Changes and maintenance

Apply settings, add teammates, or upgrade

After editing .env, finish active sessions and recreate the controller:

docker compose up -d --force-recreate --wait

A plain restart does not reload settings. Accounts and saved profiles remain in the data volume. After initial setup, you may remove both bootstrap username and password settings; changing them never resets an existing account.

Add teammates with docker compose exec controller npm run members -- create alice. Each member creates their own token. The initial account has the same private resource scope as other members.

Only the controller mounts the Docker socket. Browser sessions use isolated runtime containers. Temporary data is removed on close; saved profiles persist. The host administrator controls stored data.

Back up the volume before upgrading. Preserve the project name, and never run two controllers against one volume. Older images need an image upgrade to support the new account bootstrap and authenticated HTTP MCP flow. See the full guide for migration and platform notes.
