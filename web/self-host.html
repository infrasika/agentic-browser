1. Download the setup files

This small download contains Docker Compose configuration, setup helpers, and operating instructions. The scripts/ and deploy/ folders used below are included in this download; they are not a source checkout. The application and browser come from our two public images:

  • agentic-browser-controller
  • agentic-browser-runtime

The controller runs the service. The runtime provides Chrome, zkPass TransGate, and zkPass Schema Validator; the controller starts separate browser containers as sessions are requested and removes them afterward.

Image references are pinned by digest in deploy/release.env. The download includes configuration and documentation only, with no personal browser state. You do not need access to the source repository.

2. Prepare Docker

Use Docker Engine 26+ and Compose 2.24.4+ on Ubuntu, or Docker Desktop with its Linux engine on a Mac. Bash is required. Node.js, Chrome, and extensions do not need to be installed on the host.

Images support Linux amd64 and arm64. Apple Silicon Macs use Linux arm64 through Docker Desktop. Native Linux ARM validation is complete; a physical Mac acceptance run for the published native image is still tracked separately.

Start with one concurrent session and measure resource use. Each browser has a 2 GiB memory and 2 CPU limit, plus its proxy and controller. Only the controller mounts the Docker socket to manage session containers. Use a trusted image: this permission gives it powerful access to the Docker host.

3. Configure and start

In a new directory, download and verify the setup files. If you downloaded them with the buttons above, start at the checksum command. On macOS, use shasum -a 256 -c SHA256SUMS instead of sha256sum.

curl -fSLO https://agentic-browser.zkpass.org/self-host/download/agentic-browser-self-host.tar.gz
curl -fSLO https://agentic-browser.zkpass.org/self-host/download/SHA256SUMS
sha256sum -c SHA256SUMS
tar -xzf agentic-browser-self-host.tar.gz
cd agentic-browser
cp .env.compose.example .env.compose

The defaults work for one browser on your own machine. To change the port, public address, or browser limit, edit .env.compose before starting:

AB_PROJECT_NAME=agentic-browser
AB_PORT=3333
AB_PUBLIC_URL=http://127.0.0.1:3333
AB_MAX_SESSIONS=1

AB_PUBLIC_URL is the origin users open. Compose passes it into the application as PUBLIC_URL. Recreate the controller after changes. Keep the project name stable: it selects your private data volume.

Run these commands from the extracted setup directory. They pull the two images and run the service, environment check, and account setup inside the controller container:

bash scripts/release-compose.sh pull
bash scripts/release-compose.sh up -d --wait --wait-timeout 90
bash scripts/release-compose.sh doctor
bash scripts/release-compose.sh member create alice

Enter a password of at least 12 characters at the hidden terminal prompt. Open http://127.0.0.1:3333, sign in, and create a personal Agent credential. Create a separate account and credential for each team member.

4. Connect your Agent

For an Agent on the same machine as your deployment, use the setup helper below. Run pwd in the extracted directory to find its full path, replace /ABSOLUTE/PATH/agentic-browser, and enter the personal credential from your dashboard. The helper runs the MCP client inside your controller image; no host Node.js installation or application source files are needed:

{
  "mcpServers": {
    "agentic-browser": {
      "command": "bash",
      "args": ["/ABSOLUTE/PATH/agentic-browser/scripts/release-compose.sh", "mcp"],
      "env": {
        "AGENT_BROWSER_URL": "http://127.0.0.1:3333",
        "AGENT_BROWSER_TOKEN": "YOUR_PERSONAL_AGENT_CREDENTIAL",
        "AGENT_BROWSER_VIEW_URL": "http://127.0.0.1:3333"
      }
    }
  }
}

The controller must be running. The helper reads your project name from .env.compose. For the default loopback setup, the API address uses port 3333 inside the container; set AGENT_BROWSER_VIEW_URL to the address you open in your browser. If you configured a public domain, set both URL values to that domain, which must also be reachable from the controller. Refresh or restart your MCP client, then ask your Agent to open a website and hand the browser to you. Use the actual session link it returns, complete your steps, and click Hand back to Agent.

Give each team member their own account and credential. If the service runs on a remote Ubuntu server and your Agent runs on your Mac, use the remote-client setup below.

Connect an Agent from another machine

Install Docker locally and download and extract the same setup bundle on the Agent's machine. You do not start another server or create another member there. Pull only the client image before connecting:

bash scripts/release-compose.sh pull-client

Use this configuration with the full path to the setup folder on the Agent's machine and your private service's HTTPS address:

{
  "mcpServers": {
    "agentic-browser": {
      "command": "bash",
      "args": ["/ABSOLUTE/PATH/agentic-browser/scripts/release-compose.sh", "mcp-remote"],
      "env": {
        "AGENT_BROWSER_URL": "https://YOUR_PRIVATE_BROWSER_DOMAIN",
        "AGENT_BROWSER_TOKEN": "YOUR_PERSONAL_AGENT_CREDENTIAL",
        "AGENT_BROWSER_VIEW_URL": "https://YOUR_PRIVATE_BROWSER_DOMAIN"
      }
    }
  }
}

This runs a client from the same controller image, without mounting a Docker socket or server data. It needs access only to your service over HTTPS. Full client instructions are in docs/AGENT_CLIENT.md inside the bundle.

Both configurations use only the downloaded setup files and published images.

Remote access and day-to-day operation

For an Ubuntu server reached from a Mac, forward the service port and keep the tunnel open:

ssh -N -L 3333:127.0.0.1:3333 ubuntu@SERVER_IP

Open http://127.0.0.1:3333 locally. Cursor's port forwarding works too; use the local port it actually provides. AGENT_BROWSER_VIEW_URL must match the address reachable from your browser. It does not create the tunnel.

For direct remote access, use HTTPS and a trusted reverse proxy with WebSocket support. Only the service port is needed. Use docs/UBUNTU_PUBLIC_DEMO.md and deploy/nginx-public.conf for proxy and public-demo configuration; keep team authentication for your private workspace.

Temporary sessions remove their browser state on close. Saved profiles are opt-in and belong to one member. A saved profile is opened in a new session after restart; old tasks are not replayed. The deployment administrator can access the host and stored data.

Before upgrading, finish sessions, stop the controller, and back up the private volume. Keep the previous bundle and digests. Do not use down --volumes for an ordinary upgrade. Chrome profile downgrades may require restoring a pre-upgrade backup.

The bundle's docs/SELF_HOST.md covers member administration, configuration, recovery, and upgrades. Its architecture, release, and progress guides record supported behavior and remaining validation.
